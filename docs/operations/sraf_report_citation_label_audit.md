# SRAF 報告中的「來源編號」一致性檢查（離線契約）

## 背景

報告 LLM 可根據 `ev[].ref_no` 撰寫「來源1、來源2」，但模型輸出仍可能引用不存在的編號。原本的 prompt 僅以文字要求，不等於程式真的完成驗證。此工具建立**不呼叫 ES、SQL、LLM、不存原文、不改寫 Evidence**的保守檢核契約。

## 本層檢核範圍

輸入為報告文字與**該輪真正提供給報告 LLM** 的引用編號清單。固定檢查「來源1」、「來源2、3」等標記，輸出只包含固定狀態、引用數、唯一編號數、找不到對應引用的編號數、有效引用數。**不輸出缺少的來源號碼、不輸出原文、Prompt、uuid、時間或文件識別碼。**

保守處理上限：文字長度 200,000 字元，最多 500 個可用引用，最多 10,000 個引用標記；超過上限將標註「核對未完成」，不是「通過」。

- `labels_match`：標示過的來源編號均可對應，不代表引用內容是真的
- `unmapped`：至少有一個報告引用編號在本輪可用 Evidence 之外
- `no_labels`：報告沒有找到標準格式來源編號，不能據此推定「沒有引用依據」
- `invalid_contract`／`limit_exceeded`：本層無法安全完成核對，不能宣稱通過

## 階段與實際限制

本 PR 只建立純函式及離線測試，**尚未掛接到 `ask_with_report`、正式 Word、OpenWebUI 或 ReportJobWorker**。此分層避免在沒有試驗過誤判率前改動正式報告文字；下一個 PR 才將核對結論安全接到報告生成後的結果。

即使 `labels_match`，也**無法證明「來源1」內容真的支持旁邊句子**，更不是人工 fact-check、真實 Elasticsearch Recall 或報告正式驗收。日後需另外實機測試。
