# SRAF：核心詞正式名稱／通稱等價語意軸（待確認 PR）

## 範圍

SRAF `agent/es/query_terms.py` 的單次既有同義詞擴充 LLM 呼叫及其結果分組。
不改 Report Data Agent 提供的核心詞契約、ES mapping、日期驗證、Evidence
結構化 Event/Timeline 連結、LLM 呼叫次數或 Report Job 生成流程。

## 修改前與修改後（固定離線測試案例，非 live ES 實測）

- 輸入核心詞：`桃園機場`、`桃園國際機場`。
- 相同、固定的 LLM 回覆：`{"桃園機場": ["桃園國際機場"]}`。
- **前**：簡繁體擴充時再把 `桃園國際機場` 建成第二組核心語意軸，
  `[{"桃園機場", "桃園國際機場"}, {"桃園國際機場"}]`；
  僅寫「桃園機場」的 Evidence 無法通過必須同時命中兩軸的嚴格比對。
- **後**：同一實體名稱只有一軸 `[{"桃園機場", "桃園國際機場"}]`；
  「桃園機場」與「桃園國際機場」皆可命中。
- **反向**：官方名稱先列、通稱在後，亦能合併同一軸。
- **鏈式**：LLM 若分別回覆 A→B 與 B→C，僅在**明確同義核心詞**關聯時合併；
  不依一般文字相似、地理鄰近、共同出現而合併。
- **獨立主題**：機場與第三航廈若是兩個查詢軸，仍須各自命中；多個獨立軸
  共用的歧義非核心別名不給任何一軸使用，避免只靠該別名同時滿足兩軸。
- **Prompt**：新增官方全稱⇄通稱／常用簡稱／俗稱的雙向查漏；不確定
  一律省略，明確排除僅相關的其他機場／交通設施。

## 驗證與限制

- `tests/test_sraf_synonym_equivalence.py` 使用固定 LLM 回覆與模擬文字，
  走真正的 `compute_effective_terms`、`match_topic`、ES DSL builder。
  每個用例仍只有一次原有的同義詞擴充呼叫。
- 工作流程 `.github/workflows/sraf-synonym-equivalence.yml` 在 Python 3.10/
  3.11 安裝依賴並執行該檔及現有關鍵詞、日期 Evidence 回歸測試。
- **不保證 LLM 一定產生每個正式名稱**，只是明確引導。人工同義詞在 LLM
  關閉時的家族分組是另個待改善範圍；此 PR 不宣稱已完全修復。
- 只驗證 ES 查詢 DSL，**不等於真實 `news_test` Analyzer、Mapping 或 ES
  命中率驗收**。日期安全、真實資料召回率與 Report Job 實測仍待另外驗證。
- 本 PR 供使用者審核前／後結果，**不自動合併**。此分支與其他開放 PR
  可能同時編輯 `.codex`；合併前須處理文件衝突與獨立 GitHub Gate。
