# N-round Word publication (worker-internal)

The explicit claimed-result method generate_and_publish_word takes only the trusted configured private reports directory. It calls the bound generation closure (one shot) and existing ExportWordService, then uses the existing terminal/export fences. It does not accept arbitrary report content from HTTP or LLM output as authority. Current owner/index/question policy is rechecked immediately before rendering and after rendering; SQLite independently rechecks immutable claim, SUFFICIENT checkpoint revision and export phase in its write transaction.

A private, exclusive staged file is flushed before the no-replace hard-link publication and directory flush on POSIX. The completed status is committed only after publication. SQLite and filesystem are not a distributed transaction: an unexpected crash or ambiguous commit can leave an orphan final file, but an incomplete Job is not downloadable. Never overwrite or delete preexisting final files; operator must reconcile orphans separately. A private service-owned directory on a filesystem supporting hard links is mandatory. No conversation snapshot is written, so turn_id remains NULL. The existing owner-scoped Word download endpoint already checks completed status and expected canonical filename. No new public route or production Worker switch, no schema change. Actual private environment acceptance NOT TESTED.
