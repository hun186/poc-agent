# SRAF 正式報告輸出：來源編號與 Evidence 資訊量提醒

## 背景與使用者需求

2026-11-18 使用者曾發現送到報告模型的 Evidence 有時僅含一句會面文字，甚至只有日期，導致報告難以據此建立可靠的事件分析；同時 Report Job Word 曾產生與 SRAF 系統無關且缺乏驗證的部署結論。此階段銜接 #484 的來源編號審計與 #485 的短片段資訊量警示，納入正式 **單輪** `ask_with_report` 流程。#483 已確保零 Evidence 不呼叫 LLM。

## 設計

只使用已經完成日期／主題處理並**實際送往報告 LLM**的壓縮 Evidence 清單：

- 模型輸出後，以 `ev[].ref_no` 的有效集合比對「來源1、來源2」等字面來源標記。出現不存在的編號時，**不更動原文及來源**，而是在報告前方明確標示引用編號不一致。
- 對 `ev[].note` 進行不超限的字數、短片段、純日期片段計數。資訊量偏低時提醒：現有片段不足以確認完整背景、因果與定量結論。這是資訊量警示，**不等於片段錯誤或必然不可信**。
- 沒有任何標準「來源N」文字時只紀錄 `no_labels`，不自動認定 LLM 幻覺或結論錯誤；本層不執行跨句語意判讀。
- 報告文字保留全部模型輸出，前方增加固定且可理解的警語；日期候選搜尋上限的既有「結果不完整」提示仍有最高優先順序。
- `evidence_usage` 只增加固定 schema、狀態及安全計數，由 Word／Markdown 共用 Presenter **再做白名單驗證**後輸出「來源編號一致性」及「Evidence 資訊量提醒」。不得透過摘要附錄輸出原始問題、來源 ID、note 或私人欄位。

不新增 ES/SQL/LLM 呼叫，不改動來源過濾、時區、引用編號、ReportJobWorker 或 N-round 啟用。**通過的引用編號只代表編號能對應 Evidence，不代表具體句子有事實依據，也不能當成已完成內容核實**。

## 測試與部署界線

以合成單輪 Agent payload、假 LLM、真實 Word `ExportWordService` 與 Markdown 共用 Presenter 驗證：虛構來源、短片段、有效來源／較長片段、惡意附帶欄位、原本日期檢索不完整警示，以及不產生額外 LLM 請求。Hosted CI 覆蓋 Python 3.10／3.11。

本項未在正式 Linux、真實 `news_test` ES、Ollama、OpenWebUI 操作或完整 Word 人工閱讀上驗證；請勿宣稱真實幻覺率已下降、引用事實均正確，或 N 輪報告已接管正式 Worker。
