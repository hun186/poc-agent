# Deep report authenticated scope policy (candidate)

This binds actual verified SRAF user principals and the current active AuthStore account to operator-defined per-account exact index grants. Neither shared service keys, HTTP user fields nor model-produced index/permission values are accepted. Account creation stamp plus owner is privately digested and stored with the deep request; the current account and explicit grant are checked before each retrieval/generation phase. The request hash includes the binding and raw question. Ordinary Job behavior is unchanged; adaptive options and metadata are redacted in status.

The first supported direct-admission question contract is exactly three lines (surrounding whitespace preserved):
```
主題詞：聯合國、外交、合作
事件期間：2023-08-01~2023-08-31
分析面向：外交回應、合作進展
```
Topic terms are flexible literal search labels, not Boolean filters or exclusion commands. Date can be 不限. All listed aspects are coverage targets; the trusted branch verifier recompiles the entire exact question and compares all persisted intent fields. The server, never the prompt, selects the approved indexes. Ordinary free-form questions are explicitly unsupported by this first compiler; automatic natural-language scope derivation still needs an independent complete-query verifier.

This change is a trusted internal admission service and real Worker policy implementation, not an HTTP or production startup activation. Before enabling it, connect runtime composition, ensure deep status/list/progress/download owner generation isolation (legacy Report Job reads are username-based), and run actual authenticated API, local ES/Ollama and Linux acceptance. No private grant data or credentials in GitHub.
