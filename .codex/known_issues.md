## Current Summary

- **Acceptance boundary**: GitHub Hosted CI, OFF-0 (19 schema-only), mocked/fixture-based tests, local read-only Linux diagnostics and the new browser UI simulation are PARTIAL_ONLY_NOT_ACCEPTANCE. They do not establish actual Requirement → Schedule/Handoff → Report Job → Agent/LLM/Elasticsearch → DOCX, private TLS/SQL, or physical airgap success. Live production mutations, report submissions, service restarts or active model probes require separate operator authorization.
- **External dependencies**: Live ES mapping_incompatible and container HTTPS IP-SAN mismatch remain unresolved. WARN_ONLY SAN checking is lower assurance and must not be treated as an authenticated release; a CA-signed peer may still be wrong for an IP. Dedicated fixture source equality is a sequence of reads, not atomic against external writers. SQL v4 migration, schema, least-privilege SELECT-only diagnostics, ODBC18, lease/failover, Worker identity and DOCX integrity are unverified on private Linux.
- **Startup vs execution**: Merged #319 removed active operator LLM/ES preflight from ordinary FastAPI lifespan, explaining likely improved startup under busy Ollama; production LLM timeouts were **not extended**. #321 limits only operator DataAgent READY to 30s/no retry, #324 adds 540s *cooperative* server preflight budget. A blocked SDK call is not necessarily canceled. Open PR #322 adds operator-client Linux 600s wall-clock wait only; client timeout does **not** cancel server-side preflight/ES mutations. Historical launcher 90s timeout investigation and actual model contention are not proved resolved.
- **Inference observation limits**: Ollama is in a *different container*; a SRAF-container /proc process scan may legitimately see no candidate. OFF-1U observed 3 samples each low-load 202.5 MiB/70 threads vs busy 199.3 MiB/70 threads on the API process; that does not establish GPU saturation, Ollama queue, model identity or provider deadline. SRAF call_llm/DataAgent telemetry can observe blocking call duration and typed exception categories, not first-token/queue-vs-compute. Actual private load and provider cancellation remain NOT_TESTED.
- **Report Jobs**: SQLite v2 stores actual queued/agent_execution/docx_export/finalizing/completed/failed/interrupted stages. An old v1 running record is unobserved until recovery marks interrupted. A 30s long_running hint is **not** a timeout/deadlock/queue diagnosis; only typed exception evidence populates failure_category. The existing Word endpoint validates authorized ownership, root confinement and DOCX ZIP; real private runtime output was not independently accepted.
- **Browser Report Job UI — PR #335, merged**: /report-jobs is a static same-origin presentation of existing owner-scoped POST/status/download APIs. Token is entered in-page and never stored by the app; use trusted HTTPS or loopback, not insecure untrusted plain HTTP. Polling does not cancel work, POST response loss makes job creation uncertain, and browser memory-state is not durable across refresh. Synthetic Node VM/Hosted static tests are not a real mobile/browser screenshot or authorized production test. Vercel free-tier deployment quota errors are separate from passing GitHub CI.
- **Security boundaries**: Strict OFF-1S listener attestation can fail due procfs restrictions, per-thread FD enumeration caps, socket ambiguity or process replacement; failing closed does not prove an intruder. OFF-1U local numeric observer is deliberately nonexclusive and cannot authorize bearer. Signed URLs remain bearer until expiry. Same-host E2E preflight flock + opaque epoch and immutable pinned plans only cover verified Workers sharing same UID/mount/project/lock; no cluster-wide durable capability, hard SDK cancellation, ES transaction or already-issued work rollback. New E2E admission can be revoked; already-admitted jobs may finish on their pinned plan.
- **Product and quality**: SQL Requirement authority, Product schema v4 CAS/fencing, owner/idempotency and service principals must be retained. P2.1 oversized URL-encoded preview may return 400 vs 422 depending on unpinned versions; do not silently change its contract. Structured retrieval exclusion propagation and report evidence quality still require work and real samples. No Job Task JT-1/Workflow Registry/LangGraph implementation is established.
