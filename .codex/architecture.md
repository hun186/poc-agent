# System Architecture — SRAF (active, compacted)

## Current Summary

- **Core and boundaries:** Production FastAPI ASGI `app.py` / `sra_api/` (`api/` compatibility namespace), real Agent/LLM, Elasticsearch, SQL Server, DOCX/Word. `agent/` owns routing/retrieval/refinement/report generation; `data_ingestion/` owns ingest. This is real production code, not a mocked/demo API.
- **Source authority:** Requirement SQL Server immutable Set/Version/Snapshot/Import Run authority; `requirement_scheduler/` and `sra_schedule` own versioned Schedule/Handoff leases. API lifespan Report Job Worker and launcher-managed Schedule/Handoff Workers are distinct. Durable report phases remain in the existing SQLite ReportJobStore, **not** a new queue. Product Task integration reuses existing Requirement/Agent/Handoff/Report Job/RBAC/audit with schema-v4 and CAS/idempotency boundaries; do not infer live success from CI.
- **Privileged surfaces:** `data_reader`, `data_editor`, `db_operator`, `superuser` and Service Keys are distinct. Browser signed resource capabilities enforce representation/action; owner scoping, SQL/ES ACL and transport/TLS identity are security boundaries. No production SQL registry, credentials, host paths or model prompts in offline release evidence.
- **Release provenance:** `shared/runtime_provenance.py` plus schema-v2 `REQUIREMENT_E2E_PROVENANCE.json` govern reviewed runtime-file identities. Deployment-local Requirement SQL registry is excluded from release manifests; any selected identity is verified internally without printing registry path/contents/hash. OFF-2 verified file/Wheel byte lists require independently obtained external manifest digest; these are not themselves signed or a complete dependency inventory.
- **Operator E2E:** Superuser-only runtime evidence is separate from normal startup. Cooperative 540s preflight (not hard LLM/ES cancellation) stages an immutable E2E Plan only after all checks succeed; re-probe/failure/drift prevents new admission, while in-flight verified jobs retain their pinned Plan. Linux private same-UID no-follow lock/opaque generation fence is same-host scope, **not** cross-host distributed authorization. Real SQL/ES/LLM/Handoff/Word require explicitly authorized separate FULL_LIVE acceptance.
- **Report Job and diagnostics:** Real Agent/LLM/ES/DOCX pipeline retains owner-scoped status/download; phase timestamps and classified duration are observed at real steps, not estimated GPU throughput. Existing same-origin `/report-jobs` UI keeps bearer only in memory. OFF-1U/V/W `/proc` process/RSS snapshots have bounded, non-exclusive or observational scope and cannot authorize bearer calls; OFF-1S strict listener identity is still required. LLM and DataAgent timing instrumentation excludes prompts/secrets, cannot identify queue-vs-compute time and never replaces live behavior.
- **OFF-1 and OFF-3 operator dispatch:** `tools/sraf_airgap_off1_hub.py` reuses canonical OFF-1 diagnostics. `run_sraf_airgap_offline.sh` accepts only explicit allowlisted modes: quick, diagnose, no-network, release-files, release-policy, release-deps, wheel-files, target-platform. Quick/default does not run live Report Jobs, SQL/ES authenticated probes or model generation. Privileged SQL/ES probes and Report Job execution require separate opt-in and identity checks; the root dispatcher rejects implicit acceptance/upgrade/restore. Evidence output uses private no-follow directories, redacted enums and limited counters.
- **OFF-2 release partial checks:** `tools/sraf_airgap_off2_manifest_check.py` hashes externally pinned listed runtime files; `tools/sraf_airgap_off2_requirements_audit.py` detects unpinned direct requirements without claiming transitive lock; `tools/sraf_airgap_off2_wheel_files.py` checks externally pinned Wheel bytes, bounded ZIP metadata and RECORD contents with strict resource caps. `tools/deployment_manifest_policy.json` enumerates required release entrypoints/tools, not proof that a complete Wheelhouse exists. Invalid, unsupported, unsafe inputs fail closed; all positive statuses remain `PASS_PARTIAL`.
- **OFF-2 local target identity:** `tools/sraf_airgap_off2_linux_target.py` under `target-platform` reads bounded, no-follow Linux distro, selected CPython SOABI/libc and ODBC18 default registration. v2 checks only vendor ELF64 header on the **same** no-follow FD. v3 candidate delegates bounded static PT_LOAD/PT_DYNAMIC/DT_NEEDED name-reference parsing to `tools/sraf_airgap_off2_elf_needed.py`; it returns only an enum and count and never loads .so, resolves native libraries or outputs names/paths. A matching ELF64/DT_NEEDED subset does **not** establish loader/pyodbc ABI/TLS/SQL compatibility, signed wheelhouse, physical airgap or live system acceptance.
- **Truth boundary:** 19 OFF-0 schema checks, synthetic Hosted OFF-1/2 and operator E2E, local `PASS_PARTIAL` observations, target ABI read-only and accurate resource evidence cannot attest SQL/ES identities, live report fidelity, signed complete artifacts, fully disconnected installation/upgrade or OFF-5 restore. Keep `full_live`, unresolved ODBC native load/dependency resolution, `wheelhouse_compatibility` and `production_release_ready` explicitly **NOT_TESTED/false** until real independent proof.
