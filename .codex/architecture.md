# System Architecture

## Current Summary

- **SRAF core** is the FastAPI report-writing system (Agent/LLM, Elasticsearch, SQL Server, Markdown/Word DOCX). `app.py` is the ASGI entrypoint; `sra_api/` owns implementation and `api/` compatibility imports. `agent/` handles routing, refinement, retrieval, analysis and reports; `data_ingestion/` loads indexes.
- Requirement SQL Server **immutable Sets/Versions/Snapshots/Import Runs** are authoritative; `requirement_scheduler/` and `sra_schedule` provide separate versioned Schedule/Handoff and lease authority. Launcher-managed Schedule/Handoff Workers are separate from API lifespan's Report Job Worker. Do not add a second queue/scheduler/auth store or treat JSONL projections as SQL authority.
- Production Report Jobs use real Agent/LLM/ES/DOCX. Verified E2E semantic mock routing exists **only inside** a provenance-validated Job's execution ContextVar; tool worker threads carry the same pinned, immutable Plan. Report Job artifacts are path/root confined and DOCX ZIP/SHA verified.
- Product Task integration reuses Requirement Import, Schedule/Handoff, Report Jobs, Auth/RBAC and audit. Durable Product schema v4 supports provisioning, request idempotency, task updates, version proposals, superuser activation and CAS fences. Product P2.1 public read/preview and later UI/SQL live acceptance require independent current GitHub verification, never inference from old PR snapshots.
- Shared deployment/release provenance authority is `shared/runtime_provenance.py` and schema-v2 `REQUIREMENT_E2E_PROVENANCE.json`. Active imported modules and selected release-managed runtime inputs must match signed/reviewed bytes; inactive residue is warning only. The Requirement SQL registry remains privileged **deployment-local** and is excluded from release manifest; Linux `collect_source_evidence` resolves its selected identity for fail-closed validation without returning its contents, digest or path.
- Auth uses `data_reader`, `data_editor`, `db_operator`, `superuser` and distinct Service Key principals. Signed browser resource capabilities bind action/representation; owner isolation, SQL/ES ACL, strict transport identity and sanitized diagnostics remain hard boundaries.
- OFF-0 contract (19 schema checks) and OFF-1 diagnostics are **partial observations**. OFF-1A anonymous loopback health, OFF-1B private-IP TCP/ES HTTPS Mapping, OFF-1F local LLM, OFF-1G SQL, OFF-1H/I/J Worker/lease, OFF-1K–R same-item SQL/Handoff/Report/DOCX, OFF-1S/T API listener and read-only runtime baseline do **not** alone prove FULL_LIVE, durable cross-system consistency or physical airgap. OFF-1B warning-only ES IP-SAN diagnostic never upgrades identity to release acceptance.
- Operator E2E `GET /v1/operator-e2e/runtime-evidence` is superuser-only and distinct from normal API startup: it validates source/root/Worker evidence and probes LLM/ES within a cooperative **540s** deadline. No SDK hard cancellation, atomic ES transaction or complete private Linux acceptance. Plan is staged and published only after whole successful evidence response; already-frozen plan requires exact re-probe and fails closed on drift/timeout.
- Linux operator E2E uses an existing private UID-owned, no-follow `preflight.lock` with nonblocking exclusive `flock`: simultaneous operator checks on one host cannot overlap. Following #327, in-flight verified Report Jobs pin their admitted Plan; new E2E jobs cannot use a locally suspended Plan.
- **PR #328, pending**: under that lock, rotate a non-secret opaque same-host generation at operator preflight start; after complete success, bind the generation to this Worker's locally published Plan. New verified E2E admissions compare a bounded nonblocking shared-lock generation; a later peer Worker preflight invalidates old Worker plans **without sharing a Plan**. Different host, UID, temporary mounts/containers are outside this boundary.
- Deployment `run_sra_api.sh`, strict launcher/listener identity, OFF-1 isolated read-only scripts and optional high-load verification remain separate; never restart/mutate private production services as incidental proof.
