# API Contract

## Current Summary

- FastAPI routes live in `sra_api/routers/`; `api/` is a compatibility namespace. Public/report surfaces include `GET /healthz`, `GET /v1/models`, `POST /v1/chat/completions`, document retrieval, synchronous Word export, and owner-scoped `POST /v1/report/jobs`, `GET /v1/report/jobs/{job_id}`, `GET /v1/report/jobs/{job_id}/word`. Published artifacts require path confinement, valid DOCX and digest/provenance.
- Authenticated Requirement Import/Schedule APIs expose immutable source Set/Version/Snapshot authority, profiles, Run/Batch Item histories and authorized Handoff-published artifacts. Product schema-v4 operations use superuser-only provision/activation, canonical principal+operation+route/target+payload digest `Idempotency-Key` and CAS revision/ownership fences. Do not assert old P2.1 PR #288 endpoints or later UI are merged without latest GitHub verification.
- The superuser `GET /v1/operator-e2e/runtime-evidence?verification=release|functional` returns existing schema `requirement_e2e_runtime_evidence_v1` with deployment provenance, Worker identities, output-root fingerprint and local E2E capability evidence. Operator-only plan checks are deferred from API startup; normal production jobs are unaffected.
- `GET /v1/operator-e2e/runtime-evidence/status` is superuser-only, schema `sraf_operator_preflight_status_v1`. Fields: `state`, `generation`, `elapsed_seconds`, `scope`. Process-local states include `NOT_STARTED`, `RUNNING`, `RUNNING_OVERDUE`, `COMPLETED`, `FAILED`, `TIMEOUT`. On Linux another process holding the same-host lock may appear as `HOST_LOCK_HELD` with zero generation/elapsed and `linux_same_host_lock_observation_only` scope. This endpoint **never** reports cross-process Plan acceptance or owner/PID/credentials.
- Overlapping operator E2E preflight => HTTP **409** `external_e2e_preflight_in_progress`; cooperative deadline expiry after provider unwind => HTTP **503** `external_e2e_preflight_deadline_exceeded`; unavailable/unsafe lock => sanitized HTTP **503** `external_e2e_host_guard_unavailable`.
- A new E2E Job without its **local** authorized Plan => `external_capability_plan_unresolved`. A new Job during/after a failed/suspended plan recheck => `external_capability_plan_revalidation_required`. An operator re-probe returning a different immutable backend/probe classification => `external_capability_plan_drift`. Only a complete timely matching recheck restores local admission. An already-admitted verified E2E Job retains its pinned immutable Plan through the execution and tool-worker threads.
- **PR #328 pending:** on Linux a new verified E2E Job with an operator-published local Plan must read the same-host opaque generation via nonblocking shared lock. Mismatch, missing/corrupt/unsafe lock or concurrent exclusive operator lock fails closed with `external_capability_plan_revalidation_required`. This does not transfer authorization to other Workers or hosts and adds **no public API field/route**.
- Superuser `GET /v1/operator-e2e/batches/{batch_run_id}/items/{run_item_id}/artifact` uses durable Handoff metadata, fingerprinted output root, confinement and DOCX bytes/ZIP/SHA; no caller-supplied filesystem path. Source failure categories include `release_provenance_missing`, `release_provenance_invalid`, `active_runtime_source_mismatch`, `unexpected_active_runtime_module`, `runtime_module_shadowing` and `unexpected_runtime_input`; never expose SQL registry secrets/paths/queries.
- Signed browser resource URLs reject duplicate/unsupported query keys, bind intended action/representation and set no-store/no-referrer/nosniff headers. Production v1 Report Job and Requirement API RBAC/audit/owner isolation are unchanged.

## Operator OFF-1 CLI Contracts (not API routes)

- OFF-0's 19 schema-only checks do not attest services. OFF-1A/B/T etc. emit fixed redacted `PARTIAL_ONLY_NOT_ACCEPTANCE` and SKIP/NOT_TESTED as appropriate.
- OFF-1B ES uses private numeric IPv4 HTTPS and fixed CA; strict IP SAN is required for authoritative identity. Quick/Docker warning-only mode preserves WARN and may send Basic credentials to a CA-signed but IP-unverified peer; must not be treated as release PASS. Explicit wrong-password challenge may create account audit/lockout side effects. Mapping structural checks and transport framing limits remain bounded.
- Progressive OFF-1G–R flags check actual read-only SQL/Worker/Schedule/Handoff/same-item Report Job/DOCX in order after earlier prerequisites; OFF-1S protects token-bearing localhost GET by verifying listener/process FDs before bearer send. Every check is independently partial and requires separately authorized private deployment execution.
