建立 Excel→SQL 任務設定檔

提供資料庫管理權限（db_operator / superuser）的使用者可在此建立真正的 config/excel_to_sql/*.json 任務設定檔。建議優先選擇既有任務作為資料庫連線來源，系統會沿用其 DB 位址、帳密、加密與 ODBC driver 設定，避免業務使用者接觸敏感帳密。

基本資訊

檔名可使用安全子目錄，建立後會先進入待審。

資料庫連線

建議沿用既有任務連線；若直接填寫，JSON 會保存 DB 帳密。選擇既有設定檔時，頁面只顯示 ODBC Driver 與 trusted connection，Server、資料庫名稱、DB 使用者與密碼會由後端讀取套用該 JSON 設定檔，不會直接顯示。

將讀取並套用所選 JSON 設定檔內的資料庫連線資訊；敏感欄位（Server、資料庫名稱、DB 使用者、DB 密碼）不會顯示在頁面上。

Excel 來源

來源目錄是批次匯入時伺服器掃描 Excel 的資料夾；使用「上傳 Excel」按鈕時會先把檔案存入系統匯入記錄區，不會要求你的本機磁碟存在這個目錄。

SQL 目的地

設定目的資料表、audit table 與自動建欄預設型別。若不確定欄位長度，建議保留預設 NVARCHAR(MAX)，避免較長描述或 JSON 內容被 SQL Server 拒絕。

Excel 欄位對應

常用 SQL 型別小提醒（預設欄位型別與欄位對應 SQL 型別都可選擇或手動輸入）
  • NVARCHAR(MAX)：長文字或不確定長度的文字，例如備註、描述、原文內容；系統未填寫時也會使用這個較安全的預設。
  • NVARCHAR(255)：最多 255 個字元的短文字，例如名稱、代碼、狀態；不適合描述、JSON 或可能很長的欄位。
  • INT / BIGINT：整數；BIGINT 適合很大的流水號或計數。
  • DECIMAL(18,2)：精確小數，例如金額、重量、比例；括號可依需求調整。
  • FLOAT：近似小數，例如科學量測；不建議用於金額。
  • DATE / DATETIME2：日期 / 日期時間。
  • BIT：是 / 否、true / false 類欄位。

多欄位拼裝成 SQL 新欄位

展開 / 收合拼裝欄位說明（實體欄位、模板、比對方式與 View 模式）

目前模式：實體欄位模式

  • 匯入時會在目的資料表新增 / 寫入一個 SQL 欄位，將拼裝後完整文字保存一份。
  • 優點是查詢、匯出與後續下游消費簡單；缺點是會多佔用資料庫空間。

拼裝規則

  • 可把多個 Excel 欄位拼成實際 SQL 欄位。
  • 模板可使用 {Excel欄名} 代入每列值，例如 日期是{日期}，發生地點是{地點}，當天的敘述是{敘述}。
  • 若不填模板，會用分隔字串串接來源欄位。

欄名比對與診斷

  • 拼裝來源欄位不再另外選比對方式；系統會依「Excel 欄位對應」中相同來源欄位設定的 exact / prefix / contains 逐欄套用。
  • 沒有在單欄對應出現的拼裝來源會使用智慧比對 smart，避免把可解析的標題強制降成 exact。
  • 需要實際 Excel 標題列才能判斷的不唯一問題，會留到預掃描或確認匯入時診斷。

未來 View 模式

  • 若希望不存重複文字，可改用 SQL View / computed expression 的設計。
  • 目前任務建立頁尚未開放真正建 View；需先定義 view 名稱、欄位引用安全檢查、CREATE OR ALTER 權限與審核流程。
安全提醒：新建任務預設為 pending，不會出現在上傳任務清單；必須由 superuser 審核啟用後才能正式上傳影響 SQL。送出前會執行只依目前表單內容即可判斷的智慧檢查，攔截目的欄位重複、拼裝來源不足、來源欄位重複、模板 placeholder 未列入來源欄位等常見錯誤；拼裝來源會沿用上方相同來源欄位的比對方式；需要實際 Excel 標題列才能判斷的不唯一問題，會留到預掃描或確認匯入時診斷。

欄位比對方式說明

  • 預設 / exact：Excel 標題必須與來源欄位完全相同，適合欄名穩定的表格。
  • prefix：Excel 標題以指定文字開頭即可，例如「船名1」「船名2」。
  • contains：Excel 標題包含指定文字即可，適合欄名前後常有附註文字時使用。
